# Лабораторная 11 — CI/CD на GitHub Actions

Минимальный проект: форма (`index.html`), 4 UI-теста (Selenium + pytest), CI и CD в `.github/workflows/ci.yml`.

## Соответствие заданию

| Пункт | Реализация |
|-------|------------|
| 1. Веб-страница | `index.html` — форма с полями Name, Email и кнопкой Send |
| 2. Ветки main, dev, fix | Создаёте вручную на GitHub (см. ниже) |
| 3. 3–4 UI-теста | `tests/test_ui.py` — 4 теста Selenium |
| 4. GitHub Actions при push | `ci.yml` запускается на `push` и `pull_request` |
| 5. Ошибки ломают тесты | Тесты проверяют текст заголовка, кнопки и сообщения |
| 6–9. Ветки и PR | Сценарий fix → dev → main через Pull Request |
| 10–11. CD на GitHub Pages | Job `deploy` только для ветки `main` после успешных тестов |

1. Зайдите на [github.com](https://github.com) → **New repository**.
2. Имя, например: `lab11-cicd`, без README (проект уже есть локально).
3. В папке проекта:

```powershell

git remote add origin https://github.com/ВАШ_ЛОГИН/lab11-cicd.git

```

4. Создайте ветки `dev` и `fix`:

```powershell

git checkout -b fix

```

На GitHub должны быть три ветки: **main**, **dev**, **fix**.

## Шаг 4. Проверка CI (тесты при push)

1. Переключитесь на `fix`:

```powershell
git checkout fix
```

2. Сделайте небольшое изменение, например текст кнопки в `index.html`:

```html
<button type="submit" id="submit-btn">Отправить</button>
```

3. Коммит и push:

```powershell
git add index.html
git commit -m "Change button text"
git push origin fix
```

4. На GitHub: **Actions** — workflow **CI/CD** должен запуститься.
5. Тест `test_submit_button_text` **упадёт** (ожидается `Send`) — это пункт 5 задания.

6. Верните кнопку обратно:

```html
<button type="submit" id="submit-btn">Send</button>
```

```powershell
git add index.html
git commit -m "Fix button text for tests"
git push origin fix
```

Тесты снова должны пройти.

## Шаг 5. Сценарий с Pull Request (пункты 6–9)

**Не коммитьте напрямую в `main`.** Только через PR.

### PR 1: fix → dev

1. GitHub → **Pull requests** → **New pull request**.
2. **base:** `dev` ← **compare:** `fix`.
3. Создайте PR. Запустятся тесты (job `test`).
4. Если красный крестик — исправьте код в ветке `fix`, push; PR перезапустит проверки.
5. Когда тесты зелёные → **Merge pull request**. Код попадёт в `dev`.

Локально обновите ветки:

```powershell
git checkout dev
git pull origin dev
```

### PR 2: dev → main

1. **New pull request**: **base:** `main` ← **compare:** `dev`.
2. Дождитесь успешных тестов → **Merge**.
3. После merge в `main`:
   - снова пройдут тесты;
   - job **deploy** опубликует `index.html` на GitHub Pages (только для `main`).

Проверка CD: откройте URL Pages из **Settings → Pages** или из лога job `deploy`.

## Как устроен ci.yml

- **test** — на каждый `push` и `pull_request`: Python, Chrome, локальный сервер, `pytest`.
- **deploy** — только если `needs: test` успешен, ветка `main`, событие `push` (не PR). Загружается только `index.html` на Pages.

Если нужно изменить текст на форме в рамках задания — меняйте и **HTML**, и ожидания в `tests/test_ui.py`, иначе CI будет падать (это и демонстрирует пункт 5).
